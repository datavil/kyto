# kyto — Implementation Plan

Nov 6, 2026 · @Zafer Kosar

## 0. How to use this plan

kyto is built in 10 workstreams of numbered tasks. An agent takes one unblocked task, finishes it until its **Done when** check passes, then ticks it.

**Task protocol**

- IDs such as `3.4` never change. New tasks take the next free number; dropped tasks stay, struck through.
- Start a task only when every task under its **Depends** is ticked.
- One task = one commit on `main` (no task branches or PRs; decided by the user, Nov 6, 2026). Commit messages start with the ID: `[3.4] feature resolver`.
- A task is done when its check and the local gate (AGENTS.md "Run the whole list") pass, not before. CI runs only on demand and on release tags, not on every push (decided by the user, Nov 7, 2026).
- Reviews cite a rule by its number (`R5`). If a task is unclear, add an open question under it instead of guessing.

**Design rules** (cite as R1–R12)

- **R1 Lazy by default.** Only `collect`, `sink_*`, `pull`, `select` and `to_*` read the matrix.
- **R2 Immutable, no views.** Every method returns a new plan; every `to_*` returns a copy the caller owns.
- **R3 One return type per function.** No `Union` returns; one gene still comes back as a `pl.DataFrame`.
- **R4 Named axes.** `cells` and `genes`; no `__getitem__`, no `.X`, no `obs`/`var`.
- **R5 Typed expressions.** `CellExpr` and `GeneExpr` never mix; mixing them fails when the plan is built.
- **R6 Names fixed at plan build.** A short name is resolved once and stored in full (`log1p:CD3E`).
- **R7 No hidden state.** Layer, seed, device and memory limit are arguments; there are no global settings.
- **R8 No implicit dense arrays.** Dense output only through `to_dense(max_bytes=...)`.
- **R9 Zeros are not nulls.** An absent sparse value is 0, missing metadata is null, a removed gene raises an error.
- **R10 Coded errors.** Every error has a stable `KY-Exxx` code and a suggested fix.
- **R11 Deterministic.** The same input, plan and seed give identical output on any number of threads.
- **R12 Documented surface.** Every public item has a NumPy docstring, a `.pyi` stub and a runnable example.

**Code style**

- Rust: `rustfmt`, `clippy -D warnings`. `unsafe` only in `kyto-exec` kernels and `kyto-gpu`, each block with a `// SAFETY:` note.
- Python: `ruff format`, `ruff check` with import sorting, NumPy docstrings, full names (`cell_index`, not `cell_idx`), Polars frames named `frame`.

**Repo map**

| Path | Holds |
| --- | --- |
| `crates/kyto-error` | `KytoError`, generated from `errors.toml` (8.1) |
| `crates/kyto-store` | Zarr layout, tile I/O, importers |
| `crates/kyto-core` | Schema, expressions, name resolver, handles |
| `crates/kyto-plan` | Logical plan, optimizer, `explain`, `estimate` |
| `crates/kyto-exec` | Streaming CPU executor, SIMD kernels |
| `crates/kyto-algo` | QC, HVG, PCA, kNN, clustering, DE |
| `crates/kyto-gpu` | CubeCL kernels, cudarc bindings |
| `crates/kyto-py` | PyO3 bindings |
| `python/kyto` | Python package and `.pyi` stubs |

- [x] **3.3 Typed expressions.** `CellExpr` and `GeneExpr` with a dtype and a source tag: `Column`, `Expression { layer, gene_id }`, `Profile { layer, cell_id }`, `Embedding { name, component }`. Metadata-only parts lower to Polars `Expr`.
  - Depends: 3.1
  - Done when: `cell_column(...) & gene_column(...)` raises `KY-E202` at build; `.str` on a numeric expression fails in pyright.
  - Done: `kyto_core::Expr<A>` (`expr.rs`) is generic over a sealed axis, with `CellExpr = Expr<CellAxis>` and `GeneExpr = Expr<GeneAxis>`, so Rust code cannot mix axes at all. An expression is an `Arc`-shared `ExprNode` tree (`Source`, `Literal`, `Binary` with `== != < <= > >= + - * / & |`, `Not`, `Str` with `starts_with`/`ends_with`) plus its `ExprDtype` kind (`expr_dtype.rs`: `Unknown`, `Boolean`, `Numeric`, `String`; `of_column` maps stored dtypes, `Enum` is `String`). `Source` (`expr_source.rs`) has the four tags; `layer` is `Option` (`None` = default layer). Columns start `Unknown`; `Expression`, `Profile` and `Embedding` are `Numeric`. Operand kinds are checked as each operation is built: a wrong kind is the new `KY-E205` (`ExpressionError`, a `TypeError`); `Unknown` is accepted and left to plan build. `Display` writes the Python code that builds the expression (`cell_column('n_genes') > 200`), used in messages and `repr`. `to_polars()` (`expr_polars.rs`) lowers metadata-only trees (`col`, `lit`, `/` as true division, `&`/`|` logical, `str.starts_with`/`ends_with` after a cast to String so `Enum` columns work), `None` when a matrix or embedding source is involved. Python (`crates/kyto-py/src/expr.rs`, one macro for both axes): frozen, unhashable `CellExpr`/`GeneExpr` with the operators and their reflected forms, `.dtype` (a `kyto.dtypes` class), `.str` namespaces, `__class_getitem__`; combining a `CellExpr` with a `GeneExpr` raises `KY-E202` (`AxisError`) as the two are combined, before any data is read (R5); other operand types are `KY-E205`; `bool(expr)` (also `and`/`or`/`not`, `a < b < c`) is the new `KY-E206`. Trees deeper than `MAX_EXPR_DEPTH` (1000) are the new `KY-E207` (a 300 000-term loop segfaulted before; bug-hunter); rendering and lowering grow the stack on demand with the `recursive` crate, as Polars does. `Display` escapes non-printable characters (`\x00`, `\u2028`), so it is always valid Python. Stubs (`_kyto.pyi`) are generic over the dtype kind (`python/kyto/dtypes.py`: `ExprDtype`, `Boolean`, `Numeric`, `String`, `Unknown`): `.str` is a property with a `self: CellExpr[String] | CellExpr[Unknown]` annotation, `&`/`|`/`~` take only `Boolean`, arithmetic only `Numeric`, ordering both sides `Numeric` or both `String` (overloads), and a cell/gene mix is a pyright error too. Polars dependency of kyto-core: `lazy`, `strings`, and `temporal` (polars-expr 0.55.2 does not compile `strings` without it). Tests: `crates/kyto-core/tests/it/expressions.rs` (dtypes, `KY-E205`, `KY-E202` text, rendering, lowering evaluated on a Polars frame), `tests/test_expressions.py` (`KY-E202` for every operator both ways, `KY-E205`/`KY-E206`, repr, immutability, runtime generics, doctests of the extension and stub docstrings), `tests/typing/expressions.py` (never run; checked by `uv run pyright` with `reportUnnecessaryTypeIgnoreComment=error`, so each expected error, such as `.str` on `CellExpr[Numeric]`, fails the gate if it stops erroring).

The constructor names in `Display` for the other sources (`gene_expression`, `cell_profile`, `cell_embedding`/`gene_embedding`) are placeholders until 3.4 names them. Static checks are looser than run time in two places: pyright cannot check the kinds of `==`/`!=` (it falls back to `object.__eq__`), and a `bool` passes where `float` is typed (`x + True` type-checks, raises `KY-E205`). Run-time choices to confirm: `x == None` is `KY-E205` (null tests come with 3.7); NumPy integer and bool scalars are `KY-E205` (NumPy floats subclass `float` and work). For 3.5: a column resolved to an integer must be rechecked under `~` (Polars `.not()` on integers is bitwise), and ordering on an `Enum` column compares category order in Polars, not text. Expressions are not picklable.

## 4. Lazy plan and optimizer (`kyto-plan`)

Goal: chained methods build a DAG that the optimizer rewrites into the fewest passes over the data.

- [x] **4.1 Logical nodes.** `Scan`, `Filter`, `SelectGenes`, `TakeCells`, `MapElementwise`, `CrossCell` (scale, HVG, PCA), `WithColumns`, `Neighbors`, `Cluster`, `Sink`. Each declares which axis it changes and whether it is per-cell or cross-cell.
  - Depends: 3.3
  - Done when: every node has an output-schema function with unit tests.
  - Done: `kyto_plan::Plan` has one variant per node, each `Node<P>` (input, parameters `P`, state cached at build) in its own file with its builder (`impl Plan`): `scan.rs`, `with_default_layer.rs`, `filter.rs` (`filter_cells`/`filter_genes`, replacing 3.8's `FilterGenes`; explain lines `FILTER_CELLS`/`FILTER_GENES`), `select_genes.rs`, `take_cells.rs`, `map_elementwise.rs` (`normalize_total`, `log1p`), `cross_cell.rs` (`scale`, `highly_variable_genes` with `HvgFlavor`, `pca`), `with_columns.rs` (`with_cells`/`with_genes`), `neighbors.rs`, `cluster.rs` (`ClusterMethod` Leiden/Louvain), `sink.rs` (`Sink::Zarr`/`H5ad`). Every node implements `LogicalNode` (`name`, `method`, `changes_axis() -> Option<Axis>`, `cell_scope() -> CellScope::{PerCell, CrossCell}`, `describe`) and, except the scan, `Transform::output_schema(&PlanSchema) -> PlanSchema` (Polars' `IR::schema()` shape: from the input's schema and the parameters only). `PlanSchema` (`plan_schema.rs`) holds the members and columns as an `AtlasSchema` whose `n_cells`, `n_genes` and `nnz` are upper bounds (for 4.6/5.5), the exact `n_cells()`/`n_genes()` when known, and which `nnz` are only bounds. Stable identity: `NodeId` = position from the scan (0), depending only on the chain below. Parameters and `PlanSchema` derive serde (parameters holding expressions wait for 4.3's expression serde). Cached `NodeState` per node (`node.rs`): schema, removed genes, first node changing each axis, rewritten layers, default layer, kept gene list, so building is O(N). Handles (3.6) report a size not known exactly as `None`. Resolver (kyto-core): `with_cell_axis_changed_by`, `with_rewritten_layers`, symbol lookup over genes not removed. (9) `NodeId` as depth fits chains; a DAG with joins (none planned) would need another scheme (4.3).
