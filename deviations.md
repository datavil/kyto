# Deviations from scanpy and anndata

Every place where kyto gives different results or semantics than scanpy or anndata.
Rules in [AGENTS.md](AGENTS.md) ("Record every deviation"). Add a row in the same commit
that introduces the deviation. Keep rows short; long reasoning goes in the topic
`memory/` entry. API shape differences required by the design rules (R1-R12, for
example no `.X` and no in-place mutation) are not listed here.

Kind: `chosen` (deliberate), `gap` (not implemented yet or known difference to fix),
`inherited` (kyto follows scanpy where another reference differs).

| Topic | scanpy / anndata | Other reference | kyto | Kind | Why | Decided |
|---|---|---|---|---|---|---|
| Layer value dtype | sparse/dense `X` and `layers` of any NumPy dtype | - | layers are `float32` or `uint32` only (`docs/format.md` §4.2); the importer (2.6) converts other dtypes; negative or `> 2^32 - 1` integers cannot become `uint32` | chosen | one CellBlock type pair (5.1); `float64` inputs lose precision on import | Nov 7, 2026, plan 5.1, spec 2.1 |
| Explicit zeros in layers | CSR may store explicit zeros; `nnz` counts them | scipy keeps them unless `eliminate_zeros()` | never stored (§4.6); `-0.0` reads back as `+0.0`; `nnz` can be smaller | chosen | canonical CSR: one stored form per matrix, byte-identical stores (8.7) | Nov 7, 2026, user (2.1) |
| Unique IDs | duplicate `obs_names`/`var_names` allowed with a warning | - | `cell_id` and `gene_id` must be unique (`KY-E101`), non-null and non-empty (`KY-E111`) on write (§5.2) | chosen | IDs are the join key for every lookup (3.9) | Nov 6, 2026, plan 2.3, 2.6 |
| Names | any string for columns, layers, `obsm` keys | - | layer, embedding and graph names match `[A-Za-z0-9_.-]+` and are unique per group ignoring case (`log1p` and `Log1p` cannot both exist); column names have no `:` (§2.1, §5.6); a plan step that would write a name breaking these rules is refused when the plan is built (`KY-E215`) | chosen | names are Zarr node names (macOS and Windows file systems ignore case) and appear in `kind:name` feature names (3.5); refusing at build means the sink never fails late (R6) | Nov 7, 2026, spec 2.1; plan 4.2 |
| Unstored members | `varp`, `uns`, `raw`, dense layers stored | - | not stored in format v0 (§12) | gap | out of scope for v0; each needs a format minor version | Nov 7, 2026, spec 2.1 |
| String metadata columns | `obs`/`var` strings may be plain `object`/`string` or `category` | - | every non-ID string column is a Polars `Enum`; categorical code `-1` becomes null (§5.4) | chosen | one string encoding; category order kept | Nov 7, 2026, user (2.1) |
| Metadata dtypes | any pandas dtype (datetime, nested, complex, ...) | - | only Boolean, integers, floats, `String` IDs and `Enum` in format v0 (§5.3) | gap | v0 scope; later minor versions can add dtypes | Nov 7, 2026, spec 2.1 |
| Unsorted or duplicate CSR indices | allowed in stored CSR | scipy sums duplicates (`sum_duplicates`) | canonicalised on import: sorted, duplicates summed as scipy does (in `float32` for `float32` data) (§4.3, §12) | chosen | canonical CSR, sorted CellBlock indices (5.1) | Nov 7, 2026, spec 2.1 |
| Zeros in graphs | `obsp` CSR may store zeros | - | stored zero-weight entries kept as edges, unlike layers (§7); open until 6.6 | chosen | a distance of 0 to a duplicate cell is an edge | Nov 7, 2026, spec 2.1 |
| 10x and mtx gene keys | `read_10x_h5` / `read_10x_mtx` index genes by symbol (`var_names="gene_symbols"`, not unique) with IDs in `gene_ids` | Seurat `Read10X` also defaults to symbols | `gene_id` is the feature ID (Ensembl), the symbol goes to `symbol`; columns `feature_type`, `genome` (singular names) | chosen | unique, stable join key (§5.2, 3.9); symbols repeat | Nov 7, 2026, plan 2.6 (pbmc3k fixture already keyed by ID, 1.5) |
| 10x and mtx feature filter | `gex_only=True` by default keeps only "Gene Expression" features | - | every feature is imported; filter on `feature_type` in a plan | chosen | an import never drops data silently | Nov 7, 2026, plan 2.6 |
| Count dtype of 10x and mtx inputs | `read_10x_h5` / `read_10x_mtx` / `read_mtx` return `float32` | - | integer inputs (10x, mtx `integer`/`pattern`, integer `.h5ad` matrices) become `uint32` layers; values are equal | chosen | counts are integers (format.md §4.2, 5.1); half the bytes of a float64 sum | Nov 7, 2026, plan 2.6 |
| Numeric categoricals | an `obs`/`var` categorical with integer or float categories stays `category` | - | stored as a plain numeric column of the categories' dtype, code `-1` null; category list and `ordered` are dropped | chosen | `Enum` holds strings only (§5.4) | Nov 7, 2026, plan 2.6 |
| Old and partial `.h5ad` files | anndata reads files from anndata < 0.8 (no `encoding-type`) and `obsm`, `varm`, `obsp`, `varp`, `uns`, `raw` | - | only anndata >= 0.8 encodings (0.8 to 0.13 versions) are imported (`KY-E120` otherwise); `X`, `layers`, `obs`, `var` only | gap | v0 scope; embeddings and graphs arrive with 6.x writers | Nov 7, 2026, plan 2.6 |
| 10x v2 with several genomes | `read_10x_h5(genome=...)` picks one | - | refused with `KY-E120` (no `genome` argument) | gap | rare; keep `convert`'s surface small | Nov 7, 2026, plan 2.6 |
| `.h5ad` export layers | `write_h5ad` keeps each matrix's format (dense, CSR, CSC) and dtype | - | `sink_h5ad` (2.7) writes every layer as CSR `float32` or `uint32` (the stored dtype; no densifying, R8), indices and indptr `int32` when they fit, else `int64`; one chosen layer (`x_layer`) becomes `X`, or there is no `X` | chosen | layers are tiled sparse (§4); a round trip of a dense or `int32`/`float64` input gives CSR of the stored dtype | Nov 7, 2026, plan 2.7 |
| `.h5ad` export tables | `obs`/`var` columns keep their pandas dtype; index name as given (`_index` if unnamed) | - | `Enum` columns become categoricals (string columns of the source come back as categoricals); integer and boolean columns become nullable (`Int64`, `boolean`, ...) only when they hold a null; float nulls are written as `NaN` (anndata has no nullable float); the index is named `cell_id` / `gene_id` | chosen | the store keeps one string encoding (§5.4) and Polars has no non-nullable flag; names come from the ID columns (§5.2) | Nov 7, 2026, plan 2.7 |
| `.h5ad` export members | `obsm`, `varm`, `obsp`, `varp`, `uns`, `raw` written when present | - | `obsm`, `varm`, `obsp`, `varp` and `uns` are written empty, `raw` not at all; no compression (anndata's default) | gap | embeddings and graphs are not stored yet (6.x); `uns` and `raw` are not stored in v0 (§12) | Nov 7, 2026, plan 2.7 |
| Ordering string columns | `<`/`>` on a plain `object`/`string` column compares text; on an unordered `category` it raises `TypeError` | Polars: unordered `Enum` compares by category order | `<`, `<=`, `>`, `>=` on any unordered `Enum` column (every non-ID string column, §5.4) raise `KY-E205` when the expression is resolved, even if the source column was plain text | chosen | one rule for all string columns; stricter is safe, and allowing text order later does not break code | user, Nov 7, 2026 (task 3.5) |
| Missing values in expressions | a missing float or categorical value is `False` under `==`, `<`, `>` and `True` under `!=` (`NaN > 1` is `False`, a missing category `!= 'a'` is `True`), so `~(x > 1)` and `x != 'a'` keep it; nullable dtypes (`Int64`, `boolean`) propagate `pd.NA` | Polars, SQL: three-valued (Kleene) logic | missing metadata is null and follows Polars: comparisons and arithmetic with null are null, `null \| True` is `True`, a filter keeps only rows that are `True`, so `x > 1`, `~(x > 1)` and `x != 'a'` all drop a missing row; `is_null()` / `is_not_null()` test for it | chosen | R9 (missing is null, not a value); one rule for every dtype, as pandas' nullable dtypes | user, Nov 7, 2026 (task 3.7) |
| `NaN` in float metadata | anndata has no nullable float: `NaN` in an `obs`/`var` float column is pandas' missing value (`isna` is `True`, `NaN > 1` is `False`) | NumPy: IEEE, every comparison with `NaN` but `!=` is `False`; Polars: `NaN` is a value ordered above every number, `NaN == NaN` | the `.h5ad` importer makes that `NaN` null, so imported metadata matches pandas' `isna`; kyto's own writers keep `NaN` and null apart (format.md §5.5), and a `NaN` that kyto writes compares as in Polars (`NaN > 1` is `True`); the export writes float nulls as `NaN`, so a stored `NaN` comes back null after an `.h5ad` round trip; `NaN` in a matrix stays a value | chosen | missing is null (R9); `NaN` in an `.h5ad` float column means missing | user, Nov 7, 2026 (task 3.7) |
| Comparing with `None` | `obs['x'] == None` is `False` and `obs['x'] != None` is `True` on every row, missing or not | Polars: `col == None` and `col != None` are null on every row | `x == None` and `x != None` raise `KY-E212`, naming `x.is_null()` / `x.is_not_null()` | chosen | neither reference result is a null test; refusing it is safe, and allowing it later is not breaking | Nov 7, 2026, plan 3.7 |
| Stale derived columns | `adata[:, mask]` keeps `obs['n_genes_by_counts']`, `obs['total_counts']` and other QC columns as computed over all genes, silently | Seurat: subsetting features keeps `nCount_RNA`/`nFeature_RNA` unchanged, silently | a stored cell column whose `schema.json` records `lineage` (format.md §8) read after `filter_genes` raises `KY-E301`; `cell_column(name).recompute()` reads it recomputed instead (the executor computes it, 5.x/6.1). Columns without lineage (every imported column) are read as stored, as in scanpy | chosen | a value computed over genes that are gone is silently wrong; refusing it is safe. Imported columns have no lineage, so scanpy's behaviour remains for them | Nov 7, 2026, plan 3.8, user |
| Duplicate gene symbols | `read_10x_h5`/`read_10x_mtx` key genes by symbol and `var_names_make_unique()` renames repeats (`TBCE`, `TBCE-1`), so `adata[:, 'TBCE']` silently picks the first; `sc.get.obs_df(keys, gene_symbols=...)` raises `KeyError` ("Found duplicate entries") for a repeated symbol, without listing the genes | Seurat `Read10X` `make.unique` the same way (`TBCE`, `TBCE.1`) | genes are keyed by ID and symbols are never renamed: `gene_expression('TBCE', by='symbol')` raises `KY-E204` listing both gene IDs; `TBCE-1` is an unknown symbol (`KY-E210`); symbols come only from the gene table's `symbol` column (an `.h5ad` with symbols as `var` index and IDs in a column keeps the symbols as `gene_id`) | chosen | a symbol names a gene only when it is unique; a made-up suffix depends on row order (R11) | Nov 7, 2026, plan 3.9 |
| Stale columns after a cell filter or a layer rewrite | `adata[mask]` keeps `var['n_cells']`, `var['highly_variable']` and other per-gene statistics as computed over all cells; `sc.pp.log1p(adata)` in place keeps `obs['total_counts']` computed from the raw values; both silently | Seurat: subsetting cells keeps feature-level metadata unchanged, silently | extends the 3.8 row: a stored gene column with `lineage` read after `filter_cells`/`take_cells`, and any stored column whose `lineage.layer` was written again by a step (`log1p(into='counts')`), raises `KY-E301` unless `.recompute()`d; columns the plan computes record no lineage and are never refused | chosen | the mirror of the 3.8 rule; a value computed from cells or values that changed is silently wrong | Nov 7, 2026, plan 4.1 (agent, following the user's 3.8 decision; to confirm) |
| Repeated IDs in a selection | `adata[:, ['A', 'A']]` / `adata[['c', 'c']]` repeat the gene or cell, with a non-unique-names warning | - | `select_genes` and `take_cells` refuse an ID listed twice (`KY-E215`) | chosen | IDs stay unique through a plan (§5.2, 3.9) | Nov 7, 2026, plan 4.1 |
| PCA outputs | `obsm['X_pca']`, `varm['PCs']`, `uns['pca']` (`variance`, `variance_ratio`) | - | the cell embedding `into` (default `X_pca`, 7.2) and the gene embedding `<into>_loadings`; variances are not in the plan schema (format v0 has no `uns`, §12) | gap | loadings named after `into` so two PCAs do not clash; variance storage waits for `uns` | Nov 7, 2026, plan 4.1 (names to confirm at 6.5/7.2) |
