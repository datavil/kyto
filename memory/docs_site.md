# The docs site (task 10.5)

**Works:** `uv run mkdocs build --strict` (in the gate, about 3 s, into `target/site`).
Pages that restate another source are generated, never written: `scripts/docs_hooks.py`
(an mkdocs `hooks:` file, no plugin) adds the home page (README), the design rules
(parsed from the plan's `**Design rules**` list) and the API pages (one per `llms.txt`
section, `:::` blocks resolved by griffe from `python/` and `_kyto.pyi`, no import of
the extension). `docs/errors.md` is checked in, generated by `scripts/error_registry.py`,
because every error's `docs_url` points at it on GitHub.

**A new public item** needs nothing here: it shows up through `llms_txt.sections()`. A
new `llms.txt` section needs an entry in `API_PAGES` (the hook raises `KeyError`) and a
line in `mkdocs.yml`'s nav.

**A new migration row** goes in `docs/migration.md`; `tests/test_docs_site.py` binds
every kyto code span to the real signature (`atlas` is `Atlas`, `ky` is `kyto`, `qc`
is `kyto.qc`, a chained call may be on any public `_kyto` class). Write calls, not
prose, in the kyto column.

**Broke (each cost a debug round):**
- griffe leaves out a `.pyi` method written only as `@overload`s (no implementation:
  `Atlas.filter`, `resolve`, `explain`), silently, with no build warning. The griffe
  extension `OverloadOnlyMembers` in the hook keeps them (`extensions` goes under the
  handler's `options`, not beside it); `test_api_reference_renders_every_member` holds it.
- `importlib` loading `scripts/llms_txt.py` by path: its `@dataclass` looks the module
  up in `sys.modules`; register it before `exec_module`.
- `error_registry.py --check` scans its own source for code literals: writing a range
  name such as the storage range literally in the generator is an "unregistered code".
  The ranges come from `errors.toml`'s header instead.
- Links from `docs/` to repo files (`../../AGENTS.md`) are warnings under `--strict`;
  the hook rewrites them to GitHub URLs rather than loosening `validation`.
- Material for MkDocs prints an end-of-life banner (May 5, 2027) on every build;
  `NO_MKDOCS_2_WARNING=1` silences it. It is not a build warning.
